# Core and Repository-Root Enrollment Matrix

Decision date: 2026-09-17

This matrix is the confirmed answer to
[Review core and repository-root enrollment](https://github.com/bryan-hoang/dotfiles/issues/352).
It applies the
[sensitive-data policy](https://github.com/bryan-hoang/dotfiles/issues/350) and
the
[link and dependency policy](https://github.com/bryan-hoang/dotfiles/issues/351)
to the core portion of the
[legacy inventory](../research/04-legacy-path-and-dependency-inventory.md).

## Reading the Matrix

- `Enroll` means mise history records the canonical source as reviewed public
  plaintext.
- `Managed` means mise or bootstrap derives the destination from one enrolled
  canonical source; the destination is not another enrollment stream.
- `Repository-only` means the path remains at the converted setup-repository tip
  but is never restored under `HOME` and is never a deployment source.
- `Local` means the live path is excluded and provisioned or edited on each
  machine.
- `Remove` means the converted tip omits the entry. Existing append-only
  ancestry retains the old object.
- `Shared` is the common core profile. Application dependencies are required
  only where the corresponding approved configuration is active; this matrix
  does not broaden the effort into general package bootstrap.

Every source below `~/.config/mise/dotfiles/` mirrors its destination relative
to `HOME` directly. For example, `~/.config/mise/dotfiles/.config/git/config` is
the source for `~/.config/git/config`. Because the source root is below the
global mise configuration root, history stores it at
`config/dotfiles/.config/git/config`; there is no extra `home/` component inside
`dotfiles/`.

Mise tracks every file in that mirrored source tree exactly. It never tracks the
source tree as a directory.

## Controlling Policies

| Class                           | Granularity and autosave                                 | Sensitive controls                                                                                                                                        | Destination and mode policy                                                                                                         |
| ------------------------------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Ordinary public source          | Exact file, `autosave = true`                            | Reviewed public plaintext                                                                                                                                 | Native canonical path, or a not-enrolled managed destination when an alias or generated file is required                            |
| Sensitive-capable public source | Exact file, `autosave = false`                           | Explicit field or section allowlist; unknown fields block the initial baseline and every explicit save; values receive a private value-suppressing review | Native files capable of absorbing private data are generated destinations; local values remain in excluded application-local inputs |
| Enrollment control              | Exact file, `autosave = false`                           | Review the complete declaration and effective path set before saving                                                                                      | Must be present before bootstrap depends on it                                                                                      |
| Reviewed homogeneous directory  | Directory, `autosave = false`                            | Review every descendant before each explicit save; global exclusions remove managed destinations                                                          | Only `.config/nvim/` and `.local/share/texmf/` use this policy in the core matrix                                                   |
| Directly invoked script         | Exact regular source, `autosave = true` unless sensitive | No embedded private identity, endpoint, or credential values                                                                                              | Profile-gated bootstrap writes the managed destination with explicit executable mode; Windows realization remains platform-owned    |
| Read-only alias                 | Exact regular source, `autosave = true` unless sensitive | Same policy as its source                                                                                                                                 | Prefer a verified link; a replaceable copy fallback is allowed and must be reapplied after source changes                           |
| Repository-only legacy path     | Not enrolled                                             | Remove forbidden private data; obsolete commands become inert and lose executable mode                                                                    | No live destination; an automated anchored-path check rejects setup references to the legacy namespace                              |

Encryption is off for every row. Managed destinations and local inputs are
excluded from history. A broad `.config`, `.local`, mise `dotfiles`, or `HOME`
enrollment is forbidden.

## Repository-Only Legacy Guard

Current paths assigned `Repository-only` remain at their existing top-level
legacy paths rather than moving into a `legacy/` directory. They are records,
not canonical sources.

The converted setup repository must enforce all of these conditions:

1. No `[dotfiles]`, `[bootstrap.files]`, template, copy, symlink, script, or
   bootstrap repository declaration may use a repository-root legacy path such
   as `/.config`, `/.local`, `/.ssh`, `/AppData`, or `/src` as its source.
2. The check is anchored at the setup-repository root so legitimate mirrored
   sources such as `config/dotfiles/.config/git/config` are not rejected.
3. Obsolete command files at legacy paths are inert and non-executable.
4. Forbidden private identity, endpoint, access-topology, credential, key, and
   secret-item data is removed even when a path remains repository-only.
5. Historical-only paths are not recreated, and `.gitmodules` plus every
   `160000` entry are absent from the converted tip.

repository-maintenance ownership.

and this matrix owns the remaining 263. Cross-references do not create a second
coverage owner.

result to 176 roots and 235 files with zero X11 roots.
