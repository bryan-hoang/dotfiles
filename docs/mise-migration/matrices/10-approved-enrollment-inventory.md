## Row Contract

The records between `enrollment-roots:start` and `enrollment-roots:end` are the
complete approved root set. Each table row has exactly these fields:

```text
id | source | enrollment_path | selected_stream | kind | variant |
autosave | source_mode | destination | review | dependencies | provenance
```

`source` is the live path passed to mise tracking. `enrollment_path` is the
format-1 manifest path before variant selection. `selected_stream` is the
portable tree path used by the selected coarse variant. No two records share a
normalized source or enrollment path.

Variant codes expand exactly as follows:

| Code | Exact selector                    | Stream rule                                                                |
| ---- | --------------------------------- | -------------------------------------------------------------------------- |
| `S`  | No variants                       | `enrollment_path` is the selected stream                                   |
| `W`  | `variants = [{ os = "windows" }]` | Replace initial `home` or `config` with `home@windows` or `config@windows` |
| `L`  | `variants = [{ os = "linux" }]`   | Replace initial `home` or `config` with `home@linux` or `config@linux`     |

There is no active X11 root. A future distro-adapter effort may propose the
single selector `{ os = "linux/x86_64", profile = "x11" }` for the deferred
X11-only sources. Composable application, WSL, systemd, and machine capabilities
gate deployment; they never create competing history streams.

Review codes have these complete meanings:

| Code        | Required review and allowlist                                                                                                                                                                                                                |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PUBLIC`    | Reviewed public plaintext. Reusable credentials, private identity, private endpoints or topology, and concrete machine/account identifiers are forbidden.                                                                                    |
| `SANITIZED` | Path-specific behavior-only field or section allowlist. Unknown fields block the baseline and every explicit save; account, auth, host, proxy, private endpoint, project, and credential fields remain in excluded application-local inputs. |
| `SSH`       | Host-independent behavior only. Hosts, aliases, endpoints, keys, identities, and access topology remain in an excluded guarded local input.                                                                                                  |
| `CONTROL`   | Review the complete control source and its effective source, destination, dependency, and exclusion expansion before every save.                                                                                                             |
| `GIT`       | Approved Git behavior and public includes only. Machine/private identity, private endpoints, signing provider details, and signing-key identifiers remain local.                                                                             |
| `IDENTITY`  | Only the exact privately reviewed public/personal author identity and nonsensitive profile marker. Work/private identity and signing details remain local.                                                                                   |
| `ENV_CODE`  | Generic environment-input names and injection logic only; no environment value may be embedded.                                                                                                                                              |
| `GPG`       | Behavior-only GPG options; no key identifiers, recipients, keys, trust state, sockets, or parent-directory enrollment.                                                                                                                       |
| `TERMINAL`  | Common-intent Terminal fields only; private paths, machine names, remote endpoints, connection topology, and credentials are forbidden. Validate every locally enabled channel before saving.                                                |
| `HARPER`    | A global dictionary write is immediate consent to publish that word. Private terms use workspace or file-local dictionaries.                                                                                                                 |
| `ZEBAR`     | Writes to only the listed settings and active custom-pack files may publish automatically; marketplace state and new descendants remain excluded.                                                                                            |
| `NVIM_DIR`  | Review every descendant before each explicit save. The exact managed `stylua.toml` path and all plugin/cache/state roots remain excluded.                                                                                                    |
| `TEX_DIR`   | Review every descendant before each explicit save; only authored TeX class/style data belongs in the root.                                                                                                                                   |

`same` in the destination field means the source path itself. A semicolon
introduces additional managed destinations. `generated` destinations are
excluded from history. Writable destinations require a verified link or junction
with no copy fallback. `copy-ok` marks a read-only, replaceable copy that must
be reapplied after source changes. On Windows, changed generated outputs hold or
quarantine rather than overwrite. On Linux, mise overwrites them; see
[Linux Managed Destinations](#linux-managed-destinations).

Every row inherits the plaintext-only policy from ticket 05 and the
canonical-source/dependency policy from ticket 06. Provenance codes `07`, `08`,
`09`, and `10` name the path matrix or approval that supplies the remaining
row-specific decision; `22` names an audit gate decision.

## Destination and Rollback Policy

- Every writable destination has exactly one enrolled regular-file source and
  requires a verified link or junction. Copy fallback is forbidden.
- Read-only destinations may use a replaceable copy only where the row says
  `copy-ok`; source or repository updates require reapplication.
- Generated destinations and all local inputs, staging, state, caches, logs,
  sessions, sockets, databases, plugin stores, and service state are excluded.
- Windows application units preflight and fail atomically per application. The
  required Windows base fails as one unit. Work-machine divergent bytes are
  preserved until their public or local disposition is approved.
- Ownership-only rollback never uninstalls packages or rewinds repositories. A
  managed file is removed and a service is disabled only while setup ownership
  and unchanged state are proven. Otherwise, the resource is quarantined or held
  for manual reconciliation.
- The Windows drift sentinel is a supported-workflow block, not an absolute
  command lock. Raw mise commands can bypass it, and automatic synchronization
  can continue until manual validation detects drift.
- The built-in history watcher remains inactive until the downstream home
  validation and automatic-sync decision.

## Linux Managed Destinations

`lab/prototype-plan.ps1` generates one `E011` declaration for each Linux managed
destination in a shared or Linux row's `destination` field:

| Destination form                         | Declaration                                                        |
| ---------------------------------------- | ------------------------------------------------------------------ |
| Writable link or read-only alias         | `mode = "symlink"` to the row's source                             |
| `generated`                              | `mode = "copy"`, or `"template"` for a `.tmpl` source; mode `0644` |
| `managed` with mode `0755`               | `mode = "copy"` with `permissions = "0755"`                        |
| `copy-ok`                                | `mode = "copy"` with `permissions = "0644"`                        |
| `AppData`, `%APPDATA%`, setup-root alias | None; Windows destinations belong to `E161`, aliases to the tree   |
| Local include, `/etc`, systemd enabling  | None; see the limits below                                         |

Every declaration selects `variants = [{ os = "linux" }]`. A row in the block
below also selects that capability as the variant's `profile`. A `wsl` or
`native-linux` condition covers every Linux machine, so it needs no profile.
Destinations are not enrollment roots, so they never enter history; the managed
`Stylua` link inside `E138` is excluded by the history exclusion.

Capabilities are mise configuration environments. Each machine lists its local
capabilities in the excluded `~/.config/mise/miserc.local.toml`, for example
`env = ["wsl", "vscode-remote"]`. Mise never captures `*.local.toml` files, and
`MISE_ENV` or `-E` overrides the list for one command. Public capability names
are `wsl`, `native-linux`, `systemd`, `vscode-remote`, `kitty-graphics`, and
application names. The `E101` template reads `kitty-graphics` from `mise_env`.

Recorded limits in mise `2026.10.0`:

- Applying a `copy` or `template` entry overwrites a changed generated output
  without `--force`. The human accepted this for Linux: edits belong in the
  canonical source or a local input, and `mise dot status` reports the changed
  output as `differs` before the next apply. Windows `E161` still holds or
  quarantines changed outputs.
- `E011` does not declare `E176`. `[bootstrap.files]` has no OS or capability
  gate and fails on Windows, and `[dotfiles]` cannot set root ownership. The
  manual WSL procedure installs the source at `/etc/wsl.conf` as `root:root`
  `0644`, next to the manual WSL restart.
- `E011` does not declare the systemd user enabling of `E173` to `E175`. Mise
  user services and systemd units write their own unit files instead of enabling
  an enrolled one, and neither takes a capability gate.

## Repository-Only Guard

All repository-only legacy paths remain sanitized and inert. No dotfile,
template, copy, symlink, script, bootstrap file, or repository declaration may
use a setup-root legacy path below `/.config`, `/.local`, `/.ssh`, `/AppData`,
or `/src`, a planning path below `/docs`, or another repository-only root file
such as `/AGENTS.md` or `/GLOSSARY.md`, as a source. The check is anchored at
setup-repository root so approved `config/dotfiles/...` sources are not
rejected. Obsolete scripts are non-executable, generated/local state is absent,
and historical-only paths are not recreated.

## Approval Exceptions

- The live `~/.config/mise/config.toml` source is an approved named exception
  outside the 421-path legacy set.
- Harper global dictionary additions and writes to the six exact `Zebar` roots
  are deliberate autosave/publication exceptions.
- Terminal settings are common-intent configuration. Local Stable/Preview
  validation does not guarantee cross-machine channel compatibility.
- The four known work-machine deltas require fresh, value-suppressing
  reconciliation before work adoption; no side wins automatically.
- Append-only ancestry retains old objects and repository-only files can still
  cause Git-level conflicts, but neither class can become a setup source.
